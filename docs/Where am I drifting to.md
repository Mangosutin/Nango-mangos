
# Nango-neo カスタム辞典サービス開発ロードマップ

単なる辞書を超え、テキスト、リスト、タグ、画像などをモジュール化して独自の辞典を作成できる「スキーマ作成型カスタム辞典サービス」を目指すためのタスク一覧です 。

## フェーズ①：ローカル基盤の完成（現在のステップ）

Python (Flask) とローカルJSONを用いて、まずはPC上で完璧に動作する「自分専用の高性能カスタム辞典ツール」を完成させます 。

* **1-1. データ構造の刷新（スキーマ・ブロック対応）**
* 
`Nango-neo_template.v03.00.json` をベースにしつつ、柔軟なブロック構造に対応できるようデータスキーマを再設計する 。


* 
`word$` や `definition$` などの必須項目（`$`マーク）のルールは維持しつつ、ユーザーが定義したスキーマ（型）に従ってデータを格納できるようにする 。




* **1-2. UI/UXの改修（フロントエンド）**
* 画面のベース（`Nango-neo.v01.1.0.html`）を改修し、設定されたスキーマ（テキスト、画像、リストなど）に基づいて動的に詳細表示エリアをレンダリングする処理を実装する 。


* 追加・編集フォームも、スキーマに応じて入力フィールド（テキストエリアや画像URL欄など）が動的に生成されるように変更する 。




* **1-3. 堅牢なインポートとバリデーション**
* インポート時に `$` がついた必須項目が正しく存在するかをチェックする形式確認（バリデーション）を実装する 。


* インポートファイルの `id` はそのまま使わず、登録順に合わせてシステム側で新しいIDを自動採番する 。




* **1-4. 重複判定とデータマージ機能**
* インポート時に単語名（外来語はカッコ内のスペル等）で重複を判定する 。


* リスト型項目（タグなど）は競合がなければ自動で追加（マージ）する 。


* 自動マージできない差分・競合が発生した場合は、ユーザーにどちらを生かすか確認させるポップアップ（`ask_cnf`）を表示する 。




* **1-5. Python (Flask) ローカルサーバー化**
* LocalStorageへの依存から脱却し、バックエンド（Python/Flask）でJSONファイルを直接読み書きする最小構成のAPIサーバーを構築する 。


* 重複判定や自動マージ、ID採番などの複雑な処理をサーバー側（Python）へ移譲し、フロントエンド（JS）は Fetch API を用いて通信を行うように書き換える 。

## フェーズ②：Webサービス化へのリファクタリング

ローカルでの完成後、誰もがブラウザからアクセスできるWebサービス（SaaS）へ移行するための基盤整備を行います 。

* **2-1. マルチユーザー・認証システムの導入**
* 「誰がアクセスしてもその人の辞書が開く」ように、ユーザーアカウント登録・ログイン機能を実装する 。




* **2-2. データベースのクラウド対応 (JSON → SQL等)**
* 大人数のデータや複雑なクエリに対応するため、JSONファイルベースの管理から本格的なリレーショナルデータベース（PostgreSQLやMySQLなど）へと移行する 。




* **2-3. スキーマ（辞典テンプレート）の管理機能**
* ユーザーが新しい辞典を作る際に、「植物辞典」「雑学辞典」などのテンプレートを選択、またはゼロからスキーマ（構成ブロック）を定義できる作成画面を実装する 。





---

## フェーズ③：クラウド公開とAI連携

サービスを世に送り出し、生成AIの力を借りて辞典作成をアシストする機能を統合します。

* **3-1. サーバー・インフラへのデプロイ**
* AWSやRenderなどのクラウドホスティングサービスにアプリケーションをデプロイし、一般公開URLを発行する 。




* **3-2. 生成AI（Gemini API）の実装**
* 
`Nango-neo_template.v03.00.json` に設定したAI指示用のキー（`\\`）を活かし、ユーザーが単語を入力した際に、指定されたスキーマに沿った原稿（生物分類、緯度・経度、豆知識など）をAIが自動生成・提案する機能を組み込む 。
